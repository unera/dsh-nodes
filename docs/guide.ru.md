# dsh-nodes

Плагин DSH: удалённые узлы объявляют свои API, модель зовёт их методы.

Сервер держит реестр узлов и **справочник API**; модель видит четыре тула и не
платит контекстом за каждый подключённый узел.

```
nodes_list()      → узлы: алиасы, online, сколько молчит, какие API держит
nodes_catalog()   → справочник: номер, имя, методы
nodes_api(api)    → методы одного API со схемами аргументов
nodes_call(node, api, method, data, timeout?, sandbox?)
```

## Что уже есть

Работающий релиз (версия в `package.json`, история — в `CHANGELOG.md`):

- узлы и токены, три способа завести узел: пара по ссылке, заявка с подтверждением,
  создание в админке; self-enroll клиента;
- справочник API с версиями контрактов и защитой от конфликтов (одно имя с разными
  схемами — отказ, а не догадка);
- очередь команд: выдача строго один раз, `state`/`served` не нужны — номер команды
  и есть билет, `POST /result` принимает и поздние ответы, отмена снимает команду
  и просит узел остановиться;
- валидация аргументов по схеме метода до отправки;
- песочница `ro`/`rw`/`full` с потолком и стартовым режимом узла, эскалация через
  диалог (`sandboxStrict` спрашивает **до** запуска, обычный отказ — после);
- правила исполнения на стороне сервера (`timing`, `flushBefore`, `flushAfter`,
  `flushAround`) — реестр в `spec/SPECIAL-RULES.md`;
- присутствие по WebSocket (кадры `state`/`ping` и `state`/`pong`, сверка поколений
  `epoch` и `client_epoch`); без пакета `ws` присутствие считается по последнему
  HTTP-обращению;
- передача файлов в обе стороны потоком, `.inprogress` → переименование, потолок
  `maxTransferBytes`;
- устройство может само присылать события: нажатие кнопки в шторке, текст, начало
  нового разговора, прогрев голоса, отчёт о деградации, — и свои записи звука
  (`POST /v1/upload-file?type=voice`). Словарь — `docs/device-events.md`;
- аудит: журнал (syslog-приоритеты) и кольцо в БД для панели;
- админка страницей на `/api/dsh-nodes/admin`;
- сервис `nodes` для других плагинов: тот же вызов без диалога согласований.

Чего ещё нет:

- локальный узел 1 (встроенные MCP) — не начат;
- приём форм с устройства (`type: "form"`) — отвечает `501`;
- админский API не описан в `spec/openapi.yaml` намеренно: он приватный, третьим
  клиентам на него опираться нельзя.

Протокол для авторов клиентов — `spec/openapi.yaml` (по-английски, там же машинные
списки `x-ws-frames`, `x-client-methods`, `x-device-events`). Русский перевод
`docs/openapi.ru.yaml` отстаёт и маршруты устройства пока не описывает — читайте
английский. Полный план с обоснованиями — `docs/plan.md`.

## Подключить клиента

В админке (`/api/dsh-nodes/admin`, за логином DSH) есть кнопка «ссылка»: получается
одноразовая ссылка вида `https://host/dsh-nodes/pair?v=<код>`, живущая 10 минут.

На машине узла:

```sh
dshnc connect 'https://host/dsh-nodes/pair?v=<код>'
dshnc daemon
```

Клиент сам обменяет код на токен — подтверждать в админке ничего не нужно. Код
в базе лежит только хешем; повторное использование — `409`, просроченный — `410`.

Два других пути: заявка (`POST /v1/enroll` без кода — устройство ждёт подтверждения
в панели) и создание узла вручную в админке (токен показывается один раз).

## Установка

Пакет опубликован в npm (`@dr-co/dsh-nodes`; на момент написания npm отдаёт 0.3.25,
а этот каталог идёт впереди — что появилось после, видно в `CHANGELOG.md`):

```sh
npm install -g @dr-co/dsh-nodes
```

Поставить именно этот каталог:

```sh
npm install /path/to/dsh-nodes
```

Конфиг по умолчанию — `cordis.patch.yml` в составе пакета. Состояние:
`$DSH_HOME/storages/dsh-nodes.sqlite`, админ-токен — рядом в
`dsh-nodes-admin.token` (0600), если не задан в конфиге.

## Кто главный в правах узла

`access` (потолок), `base` (стартовый режим), `allowEscalation` и `approver` пишут
две стороны: владелец машины в панели и сам узел в `PUT /v1/announce`. Побеждает
владелец: объявление может **сузить** свои права, но не расширить. Узел, у которого
в панели стоит `ro`, остаётся `ro`, даже если объявляет `full`, а
`allowEscalation: false` объявлением не включается. Что не дали — приходит клиенту
в `warnings` ответа и строкой `policy-narrowed` в журнал. Поле, которое владелец не
трогал (`none`), узел заполняет сам.

## Маршруты

Публичные (без токена): `POST /v1/enroll`, `GET /v1/enroll/{uuid}`,
`POST /v1/pair`.
Узел (Bearer токена узла): `PUT /v1/announce`, `GET /v1/state`,
`GET /v1/commands`, `POST /v1/commands/{seq}/result`, `GET /v1/ws` (апгрейд),
`POST /v1/events`, `POST /v1/upload-file`, `POST /v1/download-file`.
Маршрута `GET /v1/catalog` нет: справочник API читается с админской стороны.

Админ (за логином DSH, не по админ-токену): `/api/dsh-nodes/admin` — страница,
`/api/dsh-nodes/op` — одна операция (создать, переименовать, выдать токен,
`events` — разрешить или запретить события узла, удалить, допустить заявку),
`/api/dsh-nodes/nodes`, `/catalog`, `/pending`, `/audit`, `/settings` — чтение.
Правка узла идёт через `op` с `{op: "update"}`: `access`, `base`, `approver`,
`allowEscalation`, `workdir`, `default_timeout`, `aliases`, `events_enabled`
(`true`/`false`, в колонке 0/1). Неизвестное поле — `400`, а не тишина: опечатка
вроде `events` иначе выглядела бы применённой. Только флаг меняет отдельная
операция `{op: "events", id, body: {enabled: true}}` — она не трогает остальные
поля узла.

### События: разрешение владельца

Колонка `events_enabled INTEGER NOT NULL DEFAULT 0` — **по умолчанию события
запрещены**, и у всех узлов, заведённых до 0.4.0, флаг после обновления выключен.
Переключатель «События разрешены» стоит на странице узла в панели.

Выключенный флаг закрывает только маршрут событий: `notify-button`,
`notify-session`, `new-session`, `voice-warmup`, `bug-report` и устаревший
`voice.want` получают `403 events_disabled`. Узел при этом на связи, `/v1/state`
и `/v1/commands` работают, команды идут, а голосовые записи
(`POST /v1/upload-file?type=voice`) принимаются как обычно — запись не событие.

## Разработка

```sh
npm test
```

Тест поднимает настоящий `http.createServer` с обработчиком плагина — cordis
для тестов не нужен. Кросс-репозиторные проверки (методы клиента в
`x-client-methods`) включаются, когда рядом лежит `dsh-node-client`; если его нет,
тест честно пропускается с указанием пути.
